# Callgraph Visualizer agent boundaries

This repository is a single deployable application with independently evolvable
Rust backend and browser frontend implementations. Read
`docs/agent-development-boundaries.md` before changing a cross-boundary feature.

## Choose one ownership role

### Backend agent

Primary write scope:

- `src/**`
- `Cargo.toml`
- `Cargo.lock`

The backend owns HTTP behavior, domain models, storage traits, project-root
resolution, source validation, preview limits, security headers, CLI behavior,
and static-file hosting.

Do not edit frontend implementation files to make a backend change pass. If an
API contract must change, follow the contract-change protocol below.

### Frontend agent

Primary write scope:

- `public/**`, except generated `public/vendor/monaco/**`
- `frontend/**`
- `scripts/build_frontend.mjs`
- `package.json`
- `package-lock.json`

The frontend owns graph state, layouts, renderers, interaction policies,
navigation UI, the inspector workbench, source-code surfaces, themes, and
browser-side API adapters.

Do not weaken backend path checks or accept arbitrary filesystem paths in a
frontend request. Do not hand-edit generated Monaco assets.

### Shared contract and integration scope

These paths require an explicit contract or integration task:

- `schema/**`
- `graphs/**`
- `callgraph.projects.json`
- `docs/**`
- `tests/e2e_visualizer.py`
- `tests/run_e2e.py`
- `tests/artifacts/**`
- `README.md`
- `THIRD_PARTY_NOTICES.md`

Neither role should make opportunistic changes in the other role's primary
scope. When two agents work concurrently, use separate worktrees and integrate
contract changes before dependent implementation changes.

## Contract-change protocol

1. Document the old and new request/response or schema behavior in
   `docs/agent-development-boundaries.md`.
2. Update backend serialization and validation.
3. Update the browser adapter in `public/js/api.js`.
4. Add or update an integration assertion in `tests/e2e_visualizer.py`.
5. Run both backend and frontend verification gates.

API fields use `camelCase`. Unknown fields in security-sensitive requests
should be rejected. Filesystem paths come only from a loaded graph and resolved
project catalog, never directly from a browser-provided path.

## Generated assets

`public/vendor/monaco/**` is generated by:

```powershell
npm ci
npm run build:frontend
```

Commit generated assets together with `package-lock.json` and the source entry
that produced them. The application must remain runnable without a CDN.

Runtime-generated `layouts/*.layout.json` files are user workspace state. Do
not commit them unless the user explicitly asks to publish a curated layout.

## Callgraph content

Before creating or editing `graphs/**/*.json`, read
`docs/callgraph-content-standard.md`, `docs/control-flow-semantics.md`, and the
scoped instructions in `graphs/AGENTS.md`. Graph descriptions are learning
content, not decorative metadata: preserve source evidence while explaining
each node's local responsibility and each edge's role in the whole flow.

## Verification gates

Backend:

```powershell
cargo fmt --check
cargo test
cargo clippy --all-targets --all-features -- -D warnings
```

Frontend:

```powershell
npm ci
npm run build:frontend
python tests/run_e2e.py
```

Contract data:

```powershell
Get-ChildItem graphs -Recurse -Filter *.json | ForEach-Object {
  cargo run --quiet -- validate $_.FullName
}
```

Do not declare a cross-boundary change complete until all applicable gates
pass against the composed application.
