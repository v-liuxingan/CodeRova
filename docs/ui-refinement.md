# 工作台视觉与交互约定

本轮参考 [distinctive-ai-design](https://github.com/houxin0010/distinctive-ai-design)
的“明确方向 → 实际截图审查 → 减法精修”流程，选择克制的源码工作台方向。
目标是降低找操作与核对源码的成本，为十分钟理解任务保留注意力；不以控件数量或装饰衡量效果。

## 视觉与布局

- 中央画布承担路径阅读，两侧承担资料选择与源码核验。标题、工具栏、正文、辅助信息分层，避免全部同字号。
- 浅色使用白色操作面与低饱和画布，暗色使用分层深色背景。蓝色表达选择和主操作，状态始终保留文字。
- 首页保留居中的输入框与同行创建按钮；工具栏分为节点导航和图操作，不增加常驻状态区。
- 图内查找与节点选择合并为一个 Tom Select 控件，结果附带所属类和源码位置。
  搜索全量符号但最多挂载 100 个候选项，不要求先加载选项才能找到远处节点；
  资料库搜索与源码搜索保留各自范围。四向按钮和方向键按屏幕位置导航，空格与居中按钮共用逻辑；搜索输入本身不移动画布。
- 节点状态、采集、编辑说明同行；次要节点操作收进末尾菜单，与画布右键共享行为和权限。
- 说明默认展开且高度受限，源码使用详情区剩余空间。保留用户侧栏宽度和全局换行偏好。
- 字体使用系统字体，不引入远程字体、CDN 或装饰性媒体。
- 按分析器提供的 `symbol.ownerKind` 区分节点：类蓝色、接口绿色、抽象类紫色、枚举琥珀色、Record 青色。
  参考 IDEA 的类型辨识方式而非照搬整套主题，保留 C/I/A/E/R 和类型文字；选中保留类型底色。
  采集状态由详情文字表达，不覆盖已知类型色；未知类型继续使用原有通用样式，不从命名推断。
- 回收站标题单行省略，悬停查看全名，操作菜单保持固定宽度。源码跳转菜单允许下拉层溢出，避免面板内部滚动与裁切。

## 组件与维护

继续使用已有 Bootstrap 状态组件、Tom Select、Floating UI、G6 和源码编辑器。
`public/workbench/surface.css` 集中管理本轮主题、字号和间距适配，不替换这些组件的行为。
菜单复用既有节点右键实现，补齐触发按钮展开状态和 Esc 焦点返回。

## 验证边界

`tests/reading_guide_e2e.py` 使用隔离图与源码，检查菜单键盘操作、外部关闭、
根节点权限、状态语义，以及亮暗主题、桌面与窄屏布局，并截图首页、详情和采集弹窗。
截图用于自查，不视为独立评审。真实陌生读者的十分钟理解与复述效果仍需另行验收。
