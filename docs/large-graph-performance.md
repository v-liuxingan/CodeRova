# 大图交互性能专项（2026-11-05）

本轮解决阅读大图时平移掉帧、从全图定位方法时停顿的问题，保留图数据、路径引用、
源码核验和当前阅读位置。性能收益用于减少理解流程时的等待，不以更多节点作为产品目标。

## 定位与改动

采样发现瓶颈主要在渲染更新，而非视口筛选：

- 缩小后节点已变成简单矩形，但连线仍生成不可读的标签和箭头。现在它们随详细节点一起按缩放级别恢复，路径和端点保持不变。
- 纯相机移动仍触发逐元素渲染钩子。使用当前 G6 5.1.1 / G Canvas 支持的 `canvas.disableRenderHooks` 跳过这类帧的重复钩子；几何、主题和状态变更仍走正常更新。
- 复用 G6 的 `optimize-viewport-transform`，大图移动时保留节点主体和连线，短暂隐藏文字等细节，停止后恢复。实现参考 [G6 内置行为源码](https://github.com/antvis/G6/blob/v5/packages/g6/src/behaviors/optimize-viewport-transform.ts)。
- 同一细节级别内，视口变化使用 `removeData/addData` 只处理进出窗口的元素。留在窗口中的元素复用原实例，细节级别或布局变化仍完整更新。
- 从全图跳到远处节点时，先完成目标视口裁剪，再设置高亮。诊断样本的状态更新量由 2,116 个降到 25 个，避免更新即将卸载的元素。

## 本机对照

同一数据、1440×960 的 Playwright Chromium 无头浏览器、相同启动/平移/全图/定位步骤，
优化前后各跑三次，下表为中位数。使用 CPU 采样，平移为 30 次每帧移动；
不与数据、节点复杂度、缩放级别未知的官网示例直接比较，也不把结果当作所有电脑的帧率保证。

本轮测试展开 3,565 个路径引用；起始视口挂载 64 个节点/62 条边，缩略视口挂载
1,066 个节点/1,065 条边。前后数据和挂载数量一致，没有通过少展示节点换取指标。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 阅读比例平移：帧间隔 P95 | 33.3 ms | 16.7 ms |
| 阅读比例平移：4 次视口 draw 累计耗时 | 119.9 ms | 17.8 ms |
| 缩略视口平移：帧间隔 P95 | 66.7 ms | 16.8 ms |
| 缩略视口平移：超过 50 ms 的长任务数 | 20 | 0 |
| 首次切换缩略视口 | 668.7 ms | 479.0 ms |
| 从缩略视口定位远处节点 | 692.8 ms | 374.1 ms |

初次加载约 1.4–1.5 秒，没有明显改善。首次进入缩略视口仍需创建大量元素，仍存在长任务；
远距离定位仍有卸载和重建成本。本轮没有改动布局算法、压缩真实关系或降低原始数据规模。
更大图应重新采样，再决定是否引入空间索引、布局 Worker 或分批绘制，不能先堆复杂度。

## 复现与回归

启动本地服务后，使用实际图的 slug：

```sh
python tests/workbench_performance.py --slug your-graph --output target/performance.json
```

脚本生成忽略目录内的临时插桩 bundle 和指标，不修改图/布局、不启动 LSP。
用 `--bundle target/previous.js` 可以对相同数据重放此前的 bundle。
测量时避免并行构建、测试或其他重负载。不要把本机真实图、截图或原始分析数据提交为基准附件。

`tests/viewport_performance_e2e.py` 使用隔离的 800 节点图，覆盖增量挂载、原元素复用、
缩略/详细切换、文字与箭头恢复、状态更新数量、亮暗主题、点击命中、位置和图文件不变。
它已纳入 `tests/run_e2e.py`；门禁检查行为与工作量，不设依赖硬件的耗时阈值。
