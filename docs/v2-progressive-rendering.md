# V2 按调用层级渐进展示

2026-10-31。解决大图首次展示范围失控、同级调用难以比较，以及展开时丢失阅读位置的问题。
本轮只改变浏览器展示，不改变 LSP 查询预算、原始调用图或 API。

## 交互规则

- 默认 **50 层调用**：入口为第 0 层，最多展示向下 50 条调用边距离内的符号。
  一条无分支长链默认包含入口及后续 50 个节点。层数可修改，不设置固定内容上限。
- 选中带“直接下游待展开”标记的边界节点，在源码面板点击“展开下游”，再展开从该节点
  起的 50 层。只是查看节点不会自动重排；“未展示”与 LSP“尚未分析”是不同状态。
- 提供可选的“个节点”模式用于宽而浅的图，默认仍为“层调用”。节点模式按广度优先
  添加指定数量的新节点；首次总数包含入口，后续数量不重复计算已展示节点。
- “从入口重新展示”按当前数值和单位重置范围及选择；默认不高亮，空白单击取消，拖动不取消。
- 搜索范围仍是完整图。选择未展示符号会展示从入口到它的一条真实最短路径；不连通符号
  单独展示，不伪造连接。搜索显式定位可超出首次展示范围。
- 展开后保留缩放，并将当前节点固定在原视口位置；横/纵方向切换保留选中上下文。

完整 JSON 目前仍由已有 API 一次加载到浏览器，**不是服务端分页或实时 LSP 续查**。
先计算当前逻辑窗口的布局，再仅将视口及缓冲区相关节点与边交给 G6；未展开节点不布局。已显示端点之间的全部真实边
保留，包括多调用点、共享目标及回环；回环不用于继续遍历。没有把子图保存回原 JSON。

## 同层布局

### 调用路径视图（当前默认）

G6 默认按调用路径展示。不同调用者共享的方法分别显示为路径引用，每个引用只有一个
父调用者；同一调用点的证据仍指向原始边，多调用点可保留多条父子连线。
路径引用不是新方法或运行时调用实例，不能用引用数量推断执行次数。

首次出现的子树在设定深度内继续展开，重复子树停在“共享引用”处，需要时单独展开。
递归或显式回环显示终止引用，避免无限展开。50 层是向下展开上限，并不要求自动枚举
所有重复路径。源码 API 只收到原始符号/调用点 ID，原始 JSON 不写入展示引用。

父节点居中于自己的子树，兄弟引用纵向同行、横向同列。高亮限定当前引用的上下游路径；
侧栏保留原始入向调用点列表，可以查找其他调用者。切换到“调用关系”仍可检查原始共享
拓扑；两个视图均由 G6 渲染，不恢复维护经典 SVG。

这项优化针对路径阅读的混乱，不保证减少节点数。真实 Codex 总入口原图 2040 个符号，
10 层路径视图中有 2974 个展示引用，包含 934 个重复引用、6 个递归终止引用。
后续已加入视口按需绘制，见下文“视口按需绘制复测”。

### 调用关系视图

按入口最短调用距离分层，纵向同层同一行，横向同层同一列。普通兄弟调用具有相同距离，
因而对齐。共享函数保留一个真实节点，以最浅层为准，跨层调用仍通过真实连线表达。

例如 A 调用 B 和 C，B 也调用 C，则 B、C 同层，B→C 是同层关系；不能同时要求
所有边都向下一层。递归和共享关系不通过复制函数或改写调用关系解决。
画面层级不表示严格执行顺序。当前布局优先层级对齐，未宣称完成密集图的全部连线避障。

## 实现与性能边界

- `frontend/v2/graph-index.js`：节点/边索引、双向邻接表和循环安全的上下游遍历。
- `frontend/v2/graph-window.js`：显示窗口、分批/分层展开、搜索路径和层级坐标。
- `frontend/v2/path-window.js`：路径引用、原始 ID 映射、重复子树按需展开与递归终止。
- `frontend/v2/entry.js`：展示范围控制、G6 更新、视口锚定和状态差分。
- 节点卡片保留简明字段，额外标记未展示的直接下游数量。
- 边界说明折叠时不创建列表，打开后分批展示；避免为一万多条说明创建隐藏 DOM。
- 高亮用邻接表代替每个节点反复扫描全量边；状态值未变化的元素不重复提交。

**50 层不是 50 个节点。** Codex 交互启动样例深度不足 50 层，默认仍展示
4,144 个节点、8,688 条边；宽图应由用户调低层数或切换节点模式。
这轮渐进展示不能自动解决该默认配置下的全部大图重绘成本，不能把节点模式的性能当作
50 层默认模式的性能。原始验收基线见 [Codex 启动验收](codex-startup-acceptance.md)。

## 视口按需绘制复测（2026-10-31）

解决的问题是拖动、定位源码时长时间阻塞，打断读者对调用路径的理解。本轮为前端优化，
不修改 HTTP API、后端或图谱数据。默认层数仍为 50，Codex CLI 总入口样例仍为 10。

- 逻辑窗口超过 300 个引用时启用视口绘制；300 是渲染策略切换阈值，不是内容数量上限。
  保留全量逻辑布局与索引，G6 仅挂载视口及周边缓冲区相关元素。移动越过缓冲区时更新，
  同一缓冲区内不反复重建。窗口尺寸变化也触发补入。
- 穿过视口的边即使两端在视口外也保留，连同真实端点一起挂载；不伪造截断边。
  包围盒保守筛选允许多挂载元素，以优先避免遗漏可见连线。
- 远处符号搜索先补入再定位；选择状态与拖动坐标保存在逻辑缓存，卸载再挂载不丢失。
- 缩放低于 0.25 时改为简化矩形，减少概览绘制文本的开销；定位符号恢复可读缩放。
  “适应画布”基于完整逻辑窗口范围，不只基于当前挂载元素。
- 平行边分组在拓扑变化时一次计算，替代 G6 内置 transform 对每条变化边扫描全图；
  多调用点、反向边和回环各自保留，状态更新不重复分组。
- 开启 Canvas 可见区域裁剪和脏矩形刷新，去掉节点阴影；符号选择器每次加载 100 项，
  搜索仍覆盖全部符号，可继续加载选项。高亮只提交当前挂载且状态变化的元素。

## 节点展开与收起

直接使用节点外沿的圆形“＋ / −”控件，无需先选中；竖向布局位于底部，横向位于右侧，
不增加卡片高度。悬停提示动作与展开预算；侧栏不再重复放置按钮。
只有对应动作可用时才显示按钮，概览简化为矩形时隐藏。按钮区域不启动节点拖动，
单击动作保留原选择；若选中目标被收起则清空选择。展开沿用当前层数/节点数设置；
收起保留选中节点，隐藏其下游，重新布局时固定选中节点的屏幕位置。操作仅影响当前
阅读窗口，不修改图谱文件、LSP 分析结果或源码证据。

路径视图按当前路径引用收起，不影响其他调用者的同名引用。关系视图只隐藏当前分支
独占的下游，仍被其他可见分支引用的节点及其后续保持可见；若下游全部共享则收起禁用。
叶节点与递归终止引用不可收起。重新展开按当前预算计算，不保存此前嵌套的展开状态；
搜索仍能重新展示已收起节点的真实路径。默认层数保持不变。

理解目标是暂时移开已读分支，集中阅读当前流程，同时能恢复并核对证据。验证包含
共享分支隔离、回环、重新展开与搜索、真实 Codex 根节点收起到 1 个引用并恢复至
2974 个引用，以及视口锚点不漂移。单元入口：`node frontend/v2/collapse.test.mjs`；
浏览器覆盖在 `python frontend/v2/demand_e2e.py`。理解效果仍按 10 分钟任务评估。


## 缩略图导航

画布右下角使用 G6 Minimap 的适配插件，展示当前逻辑窗口内全部已展开节点，不限于
主画布已挂载元素，也不包含尚未展开的下游。节点以主题色块表示，不绘制文字与密集连线。
点击或拖动缩略图定位，方向键可平移；视口框跟随主图。点击留白处限制在逻辑图边界内。

完整概览仅在逻辑数据、拖动坐标或主题变化时重建；主图平移只更新视口框，保持按需绘制。
当前 CLI 图本机复测首屏约 1.08 秒、拖拽帧间隔 P95 16.8 ms，属于单次样例测量。
浏览器验证包括全量逻辑节点计数、点击/拖动/键盘定位、主画布仍按需挂载以及高亮恢复。

缩略图集成回归发现 Canvas 脏矩形刷新会留下选中描边，现已关闭该选项，继续使用视口按需挂载与裁剪。明暗主题像素恢复测试通过，性能数字为修复后复测。


## 方向性曲线

默认连线使用 G6 cubic-vertical / cubic-horizontal，随布局方向切换。竖向节点底部出发、
顶部进入；横向右侧出发、左侧进入。平行调用点分配不同端口，保留全部边及源码 ID，
回环沿用 G6 的自环处理。全局边类型按每条边的数据选择，避免覆盖成旧折线。
曲线随节点拖动更新；视口筛选兼容数组形式的曲线偏移。这是阅读方向优化，不保证密集
跨层边自动避障。已验证构建、视口加载、展开收起、方向切换、拖动和高亮恢复。


## 连线右键收起

右键连线打开“收起此分支”，明确以边的目标节点为分支入口：保留目标节点与进入它的
连线，收起其下游。复用节点收起语义，其他路径引用或关系视图中的共享分支不受误删。
没有可独立收起的下游时禁用菜单项。右键本身不选择或高亮边；收起导致原选中内容消失时
清空选择。菜单支持 Escape、外部点击、平移、切换图谱时关闭，位置限制在窗口内。
验证入口：`python frontend/v2/edge-menu_e2e.py`，通过真实曲线命中检查菜单和分支隔离。

节点与连线共用“分支操作”右键菜单：节点右键以自身为入口，连线右键以目标节点为入口。左键仍用于选择与源码查看，右键不改变高亮。节点实点回归覆盖收起、叶节点禁用与 Escape 关闭。


## 按空间冲突决定是否重排

节点按钮及右键收起复用增量布局：新增分支优先采用连续的子树坐标，而不是把兄弟节点
分别塞入远处空位。空间充足时，已有节点及手动拖动坐标不动；若新增节点与已有分支的
布局间距冲突，则使用当前可见图的分层布局统一撑开分支，并平移整体以固定操作节点。
这是碰撞时的统一重排，尚不是只移动最少邻居的局部约束求解；其他节点可能随之移动，
手动坐标也不再作为硬约束。未展开下游不参与宽度计算。

收起时不主动压紧剩余节点，保留阅读位置。“从入口重新展示”、切换方向或视图仍会
统一排布。默认卡片尺寸下，新节点保留横向 350 / 纵向 180 的同层中心间距；曲线仍不
保证完整避障。验证包含横纵双分支连续展开：首次无碰撞时不推开兄弟节点，第二个分支
发生碰撞时撑开、保持操作锚点且同层节点不重叠。保留菜单、视口加载与高亮专项回归。


## 宽分支曲线与多调用点归并

普通跨度保持方向性三次曲线；横向跨度超过层间距离三倍时，使用固定半径的分段平滑
转弯，避免一个三次曲线在入口处被大幅拉扁。横纵布局均适用，节点拖动时重新计算。
这不是完整避障路由，密集跨分支仍可能相交或共线。

同起点、终点、kind、flowKind、label 的关系只绘制一条，标注 ×N；原始边与路径边均
保留，画布统计区分调用关系数和绘制线数。反向与不同语义不合并。选中合并线可逐个
检查调用点；高亮按组计算，但源码请求仍使用所选调用点的原始 ID。主画布仅合并视觉
表达，不修改图谱 JSON 或分析结果。视口补入、右键、源码与高亮回归覆盖归并行为。


## 不同调用者的通道分离

宽分支不再统一沿层间中线走线。同一层间带按连线横向跨度进行区间分配：重叠跨度使用
不同通道，不重叠跨度可复用通道。节点出入端口按另一端的位置排序并分散，避免不同
调用者汇入同一节点时末段共线。仅同调用者、目标与语义的多调用点继续 ×N 归并。

通道密集时增加层间距离，按常规卡片几何预留约 10 个世界坐标单位的通道间距，固定操作
节点锚点；缩小到概览级别仍会视觉密集。初次布局、展开与重排重新分配通道，拖动期间
沿用分配比例。这不是任意手动布局或跨层交叉的全局避障保证。新增测试覆盖两方向、
不同调用者独立通道、端口区分及 30 条重叠跨度的间距。


## 展开子树的空间检查

局部增量布局此前只检查节点中心间距，可能漏掉“节点矩形没有重叠、不同调用分支却
交错穿插”的情况。路径视图现在还检查相邻已展开子树的完整横向占用区间及顺序，
空间冲突时按子树宽度统一重排并固定操作节点；收起的兄弟节点不按隐藏子树预留宽度。
关系视图含共享目标，不套用树的区间检查。横纵测试均覆盖 A 子树两侧包围 B 新节点、
但各节点无碰撞的反例。此检查修正增量布局，不把连线通道分离当作布局正确性的替代。


最终通道检查使用实际卡片边界：不同节点高度或不同层间带可能使原先不同的比例通道
落在同一世界坐标，形成粗带。`separate-tracks.js` 在可用层间区域内为跨度重叠的线路
选择间隔 10 单位的轨道，并回算曲线比例；无可用轨道时保留已有路由，不伪造调用关系。
混合卡片高度、不同层间带且初始共线的反例已覆盖横纵方向。极低缩放下仍可能视觉聚合，
此规则不等于所有路径段和任意手动布局的完整避障保证。

出线规则：同一节点的全部调用统一从中心出口出发（纵向底部、横向右侧），不按目标拆分出口。不同调用者的入线端口与后续独立通道继续保留。共同出口附近的短共线段是有意的视觉表达。

扇出一致性：通道分配与最终轨道检查都以“同一调用者、同一目标层”为一组，组内共用转弯线；不同调用者之间才错开。对称节点位置和相同卡片尺寸对应对称扇出，节点本身不对称时不强制伪造几何对称。

普通扇出曲线的两个控制点固定在起终点的半程，不再随避让通道比例上下偏移；通道比例仅影响宽跨度曲线的控制点。新增左右、上下镜像测试，覆盖非零原点与不同通道比例，避免普通分支被避让参数压偏。


## 宽跨度扇出重叠修正

取消宽跨度路径的直线与圆角分段：同一调用者共用转弯位置时，这种路径会把多个远端
分支叠成一条长干线，不能靠同层重新排序解决。所有跨度现在都使用独立三次贝塞尔
曲线，统一中心出口保持不变；宽跨度的通道比例只确定控制点，不再生成共享直线段。
此前关于宽跨度分段转弯的说明由本节取代。不同目标的曲线仍可能在共同出口附近或
低缩放下视觉密集，这不是任意布局的全局无交叉保证。

验证包含横纵镜像、远距离兄弟分支中点分离，以及 G6 实际渲染 21 个同层子节点，
断言每条路径只有 M/C 指令、路径各不相同；右键分支操作与选中重置像素回归通过。
## 调用点独立展示

调用路径视图现在为每条原始调用边创建独立的目标引用，不再按目标方法合并。
例如 A 调用 B、C、B 时保留两个 B 引用和三条独立证据边；引用仍映射原始源码 ID，
重复子树仍按需展开。关系视图可以聚合相同语义的边，计数标为“条关系”，不同 order
或 condition 不合并。

同一调用方的所有出边都有明确 order 时按 order 排列并标注顺序。否则，仅在所有
调用点来自同一文件且有有效行号时按源码行稳定排列，边标注 L 行号；同行调用保持
原记录顺序，不宣称已确定求值顺序。LSP 当前未输出 order，也未解析条件、循环及
嵌套表达式求值，因此本改动保留调用点并改善源码阅读顺序，不代表完整同步执行模型。
完整执行顺序需要生成端进一步提供控制流证据，不能在前端从行号猜测。

验收：已知顺序 B/C/B 不合并，源码行排序不生成 order，折叠/展开与搜索仍指向原始
证据；真实浏览器验证调用路径、关系视图聚合证据及节点/边右键操作。
