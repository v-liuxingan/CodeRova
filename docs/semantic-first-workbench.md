# 语义优先的调用链工作台

## 问题

当前右侧工作台把“详情”和“源码”拆成互斥页签。用户阅读源码时会失去节点或调用边的
语义说明，阅读详情时又失去源码证据，视觉重心也被页签和元数据分散。调用链可视化的主要
价值应是帮助人快速建立项目心智模型，因此描述必须比原始字段更靠前，并且与源码同时存在。

## 设计目标

1. 左侧继续承担项目和场景导航，不随图节点选择频繁变化。
2. 右侧顶部固定展示当前选择的语义摘要，源码预览占据剩余空间。
3. 描述是摘要的主内容；类型、位置、置信度等事实作为辅助信息。
4. 只重排和精简现有数据，不增加后端接口、图 schema 或推断生成内容。
5. 保留右侧拖拽调宽、键盘调宽、宽屏聚焦、整体折叠、源码范围切换和查找能力。

## 本轮不仅是布局调整

本轮同时落地三层“帮助理解”能力，且都只使用现有图数据：

### 1. 图谱意图

在稳定的左侧导航区增加当前图谱概览，展示图谱 `description`、起点、终点以及节点/关系规模。
它回答“这张图试图解释什么”，切换节点时不变化，避免用户只见局部、不知全局目标。

### 2. 阅读位置

现有调用链步进器从泛化的“上一步 / 下一步”升级为带真实目标名称的阅读路标，并继续保留
分支选择和精确调用位置。它回答“我从哪里来、下一步会到哪里”，不另造第二套路由状态。

### 3. 当前语义与源码证据

右侧摘要回答“当前节点负责什么”或“这一跳发生了什么”，下方源码回答“依据在哪里”。
证据、置信度和原始位置降为第二层信息，但不会被删除。

## 信息架构

```text
┌──────────────┬─────────────────────────┬──────────────────────────┐
│ 稳定导航区   │ 调用图画布              │ 右侧工作台               │
│ 项目/场景    │ 路径与关系              │ ┌──────────────────────┐ │
│              │                         │ │ 语义摘要（顶部）     │ │
│              │                         │ ├──────────────────────┤ │
│              │                         │ │ 源码证据（自适应）   │ │
│              │                         │ │                      │ │
│              │                         │ └──────────────────────┘ │
└──────────────┴─────────────────────────┴──────────────────────────┘
```

右侧不再提供互斥的“详情 / 源码”页签。摘要区使用紧凑的纵向层级，不堆叠多张卡片：

- 第一行：目标类型、名称以及工作台操作。
- 主体：角色和描述；描述拥有最高视觉权重。
- 次要事实：文件位置、模块/归属、调用点、关系类型、置信度。
- 操作：打开源码、折叠/隐藏节点等当前已有动作。
- 较长证据和原始字段可收进原生可展开区域，避免挤压源码。

## 选择状态

### 节点

始终展示名称、节点类型、角色、描述和源码位置。模块/归属以及节点操作作为辅助信息。
没有描述时明确显示“暂无描述”，不使用名称或源码内容伪造描述。

### 调用边

以“从谁到谁的这一跳发生了什么”为阅读顺序，展示关系描述、调用点、证据、关系类型和
置信度。调用点可用时允许打开源码；不可用时展示已有的不可用原因。

### 未选择

摘要区保留紧凑占位提示，源码区继续展示自身的空状态。加载、失败和不可用状态不得导致
工作台尺寸跳变。

## 布局和交互

- 摘要区建议高度约 `160–220px`，内容较多时在自身范围内滚动或折叠次要信息。
- 源码区使用 `flex: 1` 占满剩余高度，不能因摘要出现而失去可用的阅读面积。
- 整个工作台折叠后仍保持现有窄条行为；重新展开时同时恢复摘要和源码。
- 宽屏聚焦只改变工作台宽度，不隐藏摘要。
- 分隔条的鼠标、键盘和无障碍行为保持不变。
- 选择新节点或调用边时，摘要和源码同步更新，但不触发外部编辑器。

## 验收标准

1. 页面上不再出现互斥的“详情 / 源码”页签。
2. 选中任一有源码的节点时，描述和源码在右侧同时可见。
3. 选中调用边时，关系描述、端点和调用点/不可用原因在源码上方可见。
4. 节点与调用边的现有操作仍可用，且不新增不安全的 HTML 或文件路径输入。
5. `target` / `file` 范围切换、源码查找、上下文控制、Monaco 降级路径保持可用。
6. 拖拽调宽、键盘调宽、宽屏聚焦、折叠与恢复通过现有 E2E 覆盖。
7. 在 `1440 × 980` 视口下，摘要完整可读，源码编辑区域仍有实际阅读空间。
8. 不修改后端 API、图 schema 或 Rust 代码。
9. JavaScript 语法检查、Playwright E2E 和现有后端回归全部通过。
10. 左侧能看到当前图谱的目的、起止点和规模，且切换选择时保持稳定。
11. 步进器在有相邻目标时直接显示其名称，分支和键盘行为保持一致。

## 后续语义增强轨道

以下方向仍属于产品目标，但不能仅靠前端排版可靠完成，不纳入本轮伪造：

- 给节点增加“为什么存在、输入、输出、副作用、关键不变量、所属阶段”等结构化语义。
- 给调用边增加“传递了什么、状态如何变化、为何选择这条分支”等结构化语义。
- 生成整条链的阶段划分、关键转折点、术语表和架构摘要。
- 引入 Tree-sitter、LSP 或 SCIP 提供符号、引用、类型和调用关系候选，再由源码证据校验。
- 对人工编写、静态分析和模型生成的信息分别记录来源、置信度和审核状态。

这些能力需要先设计 schema 与语义生成/校验流水线，再由前端消费；布局改造为它们预留展示
位置，但不会把模板化句子冒充为代码理解。
