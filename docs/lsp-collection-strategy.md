# LSP 采集策略评估与优化

本页保留阶段性评估；当前操作见 [工作台 Skill](skills/callgraph-workbench/SKILL.md)。
V2 页面使用内存草稿，新增节点无须先保存即可续采，预览不写文件；采纳/保存才写入。
下文立即保存检查点的描述仅适用于旧直接 API，不适用于 V2 草稿流程。

## 本轮实现

范围为 Rust 分析器、CLI 与协议集成测试。图 JSON/HTTP 字段不变，继续用 pendingNodes
表示未采集下游，issues 区分原因。前端无需新协议适配。默认不主动排除任何项目内路径。

### 主动排除

`analyze` 增加可重复的 `--exclude-path`，接受项目内相对文件或目录，例如：

```powershell
# 将这些参数追加到原 analyze 命令；仅在确认目录不属于本次理解目标时使用
--exclude-path vendor --exclude-path tests
```

规则按路径组件匹配，vendor 不匹配 vendor_extra；不支持 glob、绝对路径或 ..。
使用源码规范化后的项目相对路径匹配，大小写按实际路径字符串匹配。
排除仅停止下游遍历，已发现的边界节点和所有入向调用点仍保留，并明确记录主动排除原因。
入口被匹配时也保留入口，报告其下游待分析。该选项不会控制 rust-analyzer 的初始索引，
不能宣称能降低全部索引耗时。它可能切断通往其他目录的可达路径，需在覆盖说明中审阅。

### 性能与失败隔离

- 一次采集内按 URI 缓存项目相对路径解析（含失败），减少反复 canonicalize；不跨运行缓存。
- 保留 BFS 和符号去重，每个已发现符号最多发起一次出向查询；循环不会无限递归。
- 完整 JSON-RPC 错误响应及格式错误的调用数组只影响当前符号，其他排队分支继续查询。
- 超时、断流、无效帧不能安全恢复读取边界，仍停止会话，记录剩余队列未查询原因。
- 深度边界与预算耗尽分别记录，null 不等于空数组，查询成功不等于语义完整。

未进行本轮真实 rust-analyzer 前后耗时对比，不能把消除重复文件系统操作表述为已量化提速。

## 后续优先级

1. 完善源码版本绑定的检查点（基础页面续采已实现）。保存原始 LSP item 的 opaque data、项目/源码指纹和服务器版本；
   旧会话 item 不能未经验证直接复用。断点恢复应重新准备失效符号，不能仅保存节点 ID。
2. 将排除、深度、预算、null、失败拆为结构化边界原因，并记录初始化、索引、请求耗时。
   当前 issues 可审阅，但不适合大规模自动统计；此项需要完整契约迁移与前端筛选支持。
3. 有界并发需要独立读循环和按请求 ID 分发、取消及进程退出处理；先测服务器吞吐，
   不能把当前串行读写 Session 直接放进并发任务。并发数应可配置并受总预算约束。
4. 引入可选可信项目完整度配置：cargo features、target、构建脚本和过程宏。
   当前禁用构建脚本/过程宏，生成代码、条件编译和宏目标可能缺失；开启会执行项目代码，
   必须由使用者明确选择，不应静默改变默认值。
5. 跨项目边界目标、动态分发、函数指针和回调需要不同解析策略与证据等级。当前项目根外
   目标只记录 issues，不生成节点；扩大深度无法补齐这些关系。
6. 同步执行顺序属于 AST/控制流分析，不能从 outgoingCalls 返回顺序或源码行推导 order。

## 页面采集与人工入口（已实现）

选择真实叶子节点后，在节点右键菜单或右侧栏点击“继续采集”。只有 pendingNodes
中且没有原始出边的节点可启动，视图收起不改变资格。全图采集按钮已移除。
本轮预算默认 100，可设置 1–1000；这是资源预算，不是图的总量上限。
任务区集中展示状态、停止、预览、采纳保存和放弃。左右侧栏从与画布的边界独立收起。

“添加节点”打开源码选择器：选择或输入项目内 Rust / Java 文件，在复用的 Monaco 编辑器
中搜索、点击行号或代码行，再校验该行所属函数。无需填写列号、符号 ID 或 LSP 参数。
空白行、无法解析的符号、未知文件、校验后变化的源码会被明确拒绝。文件列表排除构建
和依赖目录，拒绝项目外路径，单文件上限 2 MiB。

校验使用 documentSymbol 定位包含该行的函数/方法，再用 prepareCallHierarchy 确认身份。
新入口使用暖色节点和人工虚线连接；确认的是函数身份，不是消息路由或运行时调用关系。
可以补充消息名及关联说明。添加后可在同一草稿从该叶子入口单独启动采集，审阅后统一保存，不主动处理无关待采分支。
已存在的函数复用原节点与证据；撤销人工边保留节点和已有静态关系。

续采重新 prepare 待采符号、核对稳定 ID；每个完成请求原子保存检查点。停止会等待当前
查询结束。服务重启保留图中的 pending/queried，内存中的入口校验 token 需重新生成。
保存时比较原图，冲突停止。源码变化后应重新分析：旧图没有完整源码指纹，不能保证旧
关系仍有效。构建脚本和过程宏禁用，依赖 PATH 中 rust-analyzer。当前入口选择只支持
同项目 Rust，不支持跨项目消费者或自动识别异步消息路由。

本次理解问题：用户遇到异步边界时，能从源码确认接收函数并继续阅读，无需猜测采集参数。
北极星验收应让陌生项目读者在 10 分钟内定位一个异步入口、说明人工关联依据，并从
新入口验证后续调用。自动化仅验证操作与数据正确，不代替这一理解测试。
