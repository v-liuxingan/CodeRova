## 1. 当前阶段结论

已经打通 **Rust CLI → rust-analyzer → 带证据的调用图 JSON → Rust API → G6 阅读器 → 源码核验**
的纵向链路，并完成 V2 目录、主题、节点信息和选择/拖拽交互的多轮迭代。

当前属于“可运行的分析与阅读基础版本”，不是“完整自动执行理解系统”。
经典版仍承载场景阅读、布局保存和完整源码工作台；V2 尚未完全接替。
项目的 10 分钟理解目标还没有完成正式陌生读者验收。

2026-10-31 补充[Codex CLI 启动真实验收](codex-startup-acceptance.md)：交互入口 LSP
静态遍历收敛至 4,144 节点/8,688 边、0 待查询；主干清单范围内 14/14 调用点命中。
这不表示动态执行完整。该原图在 G6 中约 33.7 秒可操作、拖拽帧间隔 P95 333 ms、
选中至源码展示约 16.6 秒，说明大图性能仍须优先改进。原图与人工核验图分开保存。

## 5. 下一阶段建议与验收条件

以下是待实施计划，不计入已完成能力。优先保持一次阅读任务的上下文，再扩展自动分析范围。

| 优先级 | 工作 | 解决的理解问题 | 完成条件 |
| --- | --- | --- | --- |
| P0 | V2 统一阅读动线 | 项目、场景、调用关系和证据之间切换容易丢失上下文 | 同一工作台完成入口选择、场景阅读、调用核验和返回；浏览器历史与选择状态有明确规则 |
| P0 | G6 性能基准与优化 | 大图拖拽、平移或选择延迟影响连续阅读 | 固定真实图集，记录图规模、机器/浏览器、首次加载、交互帧耗时与输入跟随；前后对比且不删减关系 |
| P1 | 按阅读需要补齐源码与布局能力 | 阅读中无法固定布局或深入核对证据 | 明确迁移清单，验证切图、刷新、主题切换及保存失败恢复 |
| P1 | 浏览器分析任务 | CLI 到阅读器的操作链仍割裂 | 可信项目/入口选择、任务进度、取消、结果与边界报告；不开放任意命令或文件路径 |
| P1 | 第二语言真实项目验收 | 当前仅证明 Rust 适配成立 | 按 Qoreon 的实际语言服务器能力选择场景，人工核对调用点、遗漏、外部边界和恢复流程 |
| P2 | 稳定身份与增量分析 | 源码变化后难以追踪旧图与新结果 | 定义身份与失效策略，验证移动、重命名、调用变化和缓存失效，不静默沿用旧证据 |
| P2 | 业务解释与场景辅助生成 | 静态符号关系还不足以理解任务目的 | 生成解释逐项关联证据，未知项显式标注，保留分支/循环/异步与失败路径 |

每轮除工程检查外，应选择一个陌生项目场景进行 10 分钟复述与源码核验。
正式验收按[产品战略](product-strategy.md)的五维评分执行：至少 8/10，源码证据维度满分；
以至少 5 位陌生读者的固定任务验证目标达成率，不能用测试通过数代替理解效果。
