# LSP 采集扩展边界

状态：设计约定，尚未完成下述结构重构。当前实际支持仍为 Rust/rust-analyzer 与 Java/JDT LS。
本轮只确定内部扩展路线，不新增语言、启动配置、HTTP 字段或图格式，不迁移现有图。

## 要解决的问题

用户应能在不同项目中沿同一套操作阅读、核验和续采调用链。语言差异不能使递归方法重复、调用点丢失，或让读者把采集失败理解成“没有调用者”。
验收以同一份源码的正反向关系一致、重复续采无重复事实、源码位置可核验为基础；十分钟理解任务仍按 product-strategy.md 单独验收。

当前已有可复用基础：collector.rs 统一调度、预算、循环终止和合并；resume.rs 管理续采差异与草稿；session_cache.rs 管理会话；前端按图事实展示循环引用。
当前耦合点：provider.rs 的 Language 同时决定启动、请求修正与符号显示；mod.rs 的 node 直接从 CallHierarchyItem 生成身份；JavaSymbols 同时承担文档索引、身份修复、修饰符和实现关系。
Java 反向递归的复现证明，协议返回的位置不总能直接充当持久化身份；单独补一个 Java 分支不能作为后续接入模式。

## 分层与禁止跨越的边界

```text
可信启动配置 / 会话池
        ↓
LSP 标准客户端 + 服务器配置档案（能力、兼容规则）
        ↓
共享归一化：声明身份、项目路径、调用位置、查询结果状态
        ↓
统一采集器：调度、预算、循环终止、合并、统计、取消
        ↓
图事实与草稿 → 同一套前端
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 标准客户端 | 生命周期、编码、请求、取消、错误、能力记录 | 业务图去重、猜测语言语义 |
| 服务器档案 | 服务器初始化选项、有证据的协议兼容处理 | 复制采集器、直接修改图或用户说明 |
| 共享符号索引/归一化 | 项目内路径、声明位置、调用点校验、明确的失败状态 | 按相似名字猜测符号、无限追加查询 |
| 可选语义增强 | 类别、修饰符、实现候选及不确定性 | 将候选实现当成已发生调用 |
| 采集与持久化 | 单一图修改所有者、去重、预算、检查点、用户数据保留 | 接收未归一化项、判断 Java/Python 等语言名 |

接入新语言不得向 collector/resume/frontend 增加语言分支。优先使用标准档案；确有返回行为差异才增加服务器兼容规则。
暂不建设动态插件加载器、脚本规则引擎或多语言 AST 框架；先用静态注册和少量明确接口，避免维护一个比采集业务更复杂的扩展系统。

## 内部输入契约（拟定，不是新增图 schema）

- `ResolvedSymbol`：已校验项目内声明、身份依据、展示信息，以及独立的服务器请求句柄。
- `CallFact`：caller、callee、一个或多个 caller 文件内的精确调用范围；方向只影响查询，不翻转真实边。
- `QueryOutcome`：已确认事实与完成状态分别返回。区分 complete、partial、unsupported、ambiguous、failed、cancelled；有效事实可保留，但不把未完成查询标成已查询完整。
- 请求句柄保存原始 CallHierarchyItem 及不透明 data；只在当前服务器会话使用，不作为持久 ID，不写入用户图或日志。
- 标准身份键使用项目范围、规范化相对文件、声明位置和必要的消歧信息。展示标签独立，不用删掉返回类型等显示格式操作修改身份。
- 以声明位置识别不同重载、嵌套函数和同名方法；无唯一依据时返回 ambiguous。不得只用文件行号、名称或容器名称合并。
- 一个方法对应一个图节点；同一方法对在不同调用点产生不同边。没有调用点的实现候选使用独立关系类型，不能伪造调用位置。

LSP 未提供可跨会话、跨服务器、跨源码版本使用的通用符号主键。服务器 data 也不是这个主键。不能承诺更换服务器或移动源码后 ID 自动不变。

## 身份归一化流程

1. 验证 URI、项目边界、位置编码和范围。保留协议原始 URI 给服务器，文件身份使用现有安全路径解析结果。
2. 标准档案接受经验证的声明 selectionRange；入口、正向目标、反向调用者、显式续采和实现候选都经过同一个解析入口，避免只有某一方向被修正。
3. 当档案声明返回位置可能是调用位置时，复用共享文档符号索引查找声明。索引负责范围包含、最内层候选及唯一性；签名等服务器格式比较由档案提供。
4. 不能对反向调用者的调用语句直接 prepare 来猜调用者：该语句可能解析成被调用方法。位置、符号种类、身份判别必须共同支持匹配；仅“最内层包含”不够。
5. 无法确认时保留已确认事实并记录原因，当前分支留待处理。不得通过放宽项目路径或静默折叠同名节点消除错误。

文档符号并非所有服务器都支持，返回还可能是层级 DocumentSymbol 或扁平 SymbolInformation。共享解码层区分两者；扁平项没有 selectionRange，不能把 range.start 假装成精确声明名位置。需要独立的声明证据，否则报告能力限制。
不对每个标准符号强制额外请求文档索引或 definition；只有所需兼容策略才调用，避免为统一接口牺牲正常服务器的性能。

## 能力与兼容规则

能力来自 initialize 结果、已验证档案和运行时响应。LSP 的 callHierarchyProvider 没有分别声明 incoming/outgoing 的独立能力位；不得虚构协商字段。请求若返回 MethodNotFound，记录当前会话的实际不支持状态并给出明确结果。
不宣称支持尚未实现的动态注册；按当前客户端协商能力运行。文档符号、implementation 等增强能力缺失，不应阻断已确认的标准调用关系。

兼容档案按服务器实现管理；记录配置指定身份、可用的 serverInfo、规则证据及验证版本。版本未知时不能仅凭 Java 扩展名启动某个 JDT 专用修正。每条规则必须有适用条件、复现 fixture、失败行为和移除条件。

现有 JDT 规则迁移：

| 已验证差异 | 共享能力 | JDT 规则职责 |
| --- | --- | --- |
| incoming 的 selectionRange 落在调用语句 | 文档符号缓存与声明候选查找 | 选择解析策略、校验 JDT 的名称/签名格式 |
| outgoing 使用 range.start，可能受 Javadoc 影响 | 原始句柄与请求副本分离 | 仅修正发送副本的查询锚点 |
| 缓存调用包装对象保留旧调用者上下文 | 请求编排与会话互斥机制 | fresh prepare 的前置步骤与一致性验证 |
| Java 类别、修饰符、实现候选 | 可选语义增强入口 | Java 语义提取，不参与核心递归判定 |

prepare + outgoing 若依赖服务器共享上下文，必须作为档案要求的一个原子请求序列执行；不能把两次各自成功等同于并发下身份一致。只限制受影响序列，其他标准查询仍走已有有界并发。

## 性能、失效与安全

- 共享符号索引以会话身份、文件 URI 与文档版本/内容指纹为键；同一版本的并发读取合并为一次请求。变更、重启或切换配置后失效，不能仅按 URI 永久缓存。
- 请求句柄不跨会话复用；从持久图续采时重新确认声明。变更后的身份不能靠旧位置强行关联。
- 额外身份解析请求受全局取消、超时、并发和有界工作量限制。复用现有采集预算语义，并分别统计图查询与辅助协议请求，避免新增“无限回退”路径。
- 默认档案不额外启动语言工具链、不执行项目脚本；启动命令仍只来自可信本地配置。
- 自定义服务器不能通过浏览器请求指定任意命令、路径或工作目录。URI/项目边界检查先于读取缓存和请求源码。
- 协议诊断不记录源码全文、opaque data 或凭据；可发布测试只使用合成源码和脱敏协议样本。

## 兼容与分步迁移

第一步：建立归一化入口和内部类型，保持 Rust/Java 现有输出不变。把 Java 的协议位置修正移出可选语义增强，将文档符号缓存提取为共享模块；保留 Java 修饰符处理。
第二步：把 Language 的请求行为拆为静态服务器档案，默认实现标准 LSP；启动配置、语言 ID、显示文本与服务器兼容策略分别归属，不新增通用开关堆。
第三步：用参数化协议 fixture 运行统一契约测试，再用现有真实 rust-analyzer/JDT LS 用例验收；之后才接入下一种语言。

现有 stable_id 算法及 Rust/Java 的身份输入在迁移中保持兼容，使用黄金样本逐项比对。内部新类型不等于立即替换 ID 算法。若未来必须升级身份格式，单独设计图版本、旧 ID 映射、布局与说明迁移并走共享契约流程；不得在一次续采中静默生成另一套 ID。
现有错误图的去重清洗是独立数据修复任务，不能顺带删除用户节点或说明。更换服务器时默认重新确认或新建图；跨服务器自动合并不属于本轮承诺。

## 新服务器准入：一套测试，不复制一套业务

| 测试组 | 必须断言 |
| --- | --- |
| 直接/相互递归，正向/反向 | 有界终止，方法 ID 一致，多调用点不丢失 |
| 重载、同名、嵌套函数 | 不误合并；缺少唯一依据明确报告 |
| 调用位置与声明位置混淆 | 归一化后身份一致；错误证据不生成节点 |
| null、空数组、错误、部分返回 | 不把未知等同无关系；成功事实不被增强失败抹除 |
| 不支持的方向/增强能力 | 明确 capability 限制，不伪造“查无结果” |
| 并发、预算、取消、迟到响应 | 有界请求；需要原子的请求序列不串上下文 |
| 中文路径、URI 别名、UTF-16 非 BMP | 身份与证据位置一致，项目外读取拒绝 |
| 同一节点重复续采、保存/放弃 | 新增统计为实际差异，未采纳不改磁盘 |
| 文件变化、配置切换、会话重启 | 旧缓存和句柄不误用，历史节点不静默重绑定 |
| 标准通路成本 | 正常调用不因兼容框架增加不必要的辅助请求 |

接入交付物限于：启动/文件识别登记、所需服务器档案、该服务器的合成 fixture 和真实服务器验收记录；只有需要额外语义时才增加增强模块。若接入要求修改采集调度、合并算法或前端语言分支，应先说明共享契约缺了什么，而不是复制现有语言实现。
动态语言的反射、运行时分派和服务器未索引代码仍存在事实边界；不能靠 references 回退自动冒充调用关系。

## 依据与当前验证范围

本设计对照当前 provider.rs、java.rs、semantics.rs、collector.rs、mod.rs、session_cache.rs。当前真实递归验证仅覆盖 Rust/Java；不能据此声称 Python、Go、TypeScript 或其他服务器已支持。
协议依据：[LSP 3.17 Call Hierarchy 原文](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/language/callHierarchy.md)：请求句柄的 data 应保留，incoming 与 outgoing 的调用范围均属于调用者。这里的分层、缓存和准入要求是项目设计决策。
