## 范围与环境

使用当前本地代码（包含双热会话缓存、单次校验文件去重、阶段计时），debug 构建。
入口：Spring Framework 7.0.10 的 `spring-context/src/main/java/org/springframework/context/support/AbstractApplicationContext.java:581`，`refresh()`。
入口文件 SHA-256：`02ed1a7f3a1569344103f8d15cc9fa4f67c96f0c16d04661ea154cd2507f6f0f`。
源码为本地发行目录，没有 Git revision 可记录。

按页面相同 HTTP 草稿流程：项目文件列表 → 首次入口校验 → 额外一次热入口校验 → 创建根图 → 草稿采集 → 导出独立结果。
使用新服务进程与新 JDT LS 进程，复用原磁盘工作区/Gradle 缓存，**不是清空磁盘索引的冷启动**。
JDT LS 1.64.0、Zulu JDK 25.0.5，现有 Java 配置，堆上限 2 GiB。
使用隔离目录和临时端口；未覆盖用户图，没有新增路径排除，包含测试源码。
预算 1000 次出向查询；页面续采按预算遍历，没有使用 CLI 三层截断。多实现边界按当前规则等待选择。
本次是单次实测，不能代表稳定百分位或与旧版本的公平端到端对照。

## 结果与边界

- 2595 个节点（含根），3786 条关系。
- 1000 次查询尝试，998 个符号查询成功；1597 个待处理符号。
- 其中 1511 个仅由多实现候选关系到达，等待用户/AI 选择；另有 5 个仅由实现关系到达但至少存在单实现入口，81 个具有其他入向关系。这些数字按当前图入边结构分类，不是运行时覆盖率。
- 560 个节点来自 src/test 或 src/testFixtures；本轮没有额外排除测试源码。
- 校验通过：4750 个可核验源码位置，0 错误、0 警告。校验成功不等于调用关系语义完整。
- 达到预算后结束，尚未全量收敛；不自动重试或无限扩展。

4 条采集 issue：

1. AbstractBeanDefinition.overrideFrom(BeanDefinition)：JDT 调用层级排序异常，Comparison method violates its general contract。
2. AbstractBeanDefinition(BeanDefinition) 构造器：相同排序异常。
3. ReflectionUtils.MethodFilter.matches(Method)：候选实现定位时 JDT 内部 NullPointerException。
4. ReflectionUtils.MethodCallback.doWith(Method)：候选实现定位时相同内部异常。

平台隔离了这些错误并继续其他分支，未将失败项标记为完整解析。

## 后续优化依据

1. 优先定位 JDT 出向查询长耗时，给慢查询明确提示与可恢复边界；不能仅靠减少图校验解决总耗时。
2. 评估实现候选展开策略和测试源码范围，用户明确选择后再缩小；不能静默删边来制造提速。
3. 草稿检查点累计 77.7 秒，值得优化比较与复制；保留每步恢复和冲突保护。
4. 补齐 didOpen/通知写入计时，避免将未测量时间误认为纯索引。
