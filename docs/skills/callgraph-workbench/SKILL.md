# Callgraph 工作台

目标是交付可核验的执行流程，让读者理解入口、关键分支、交接与边界。图大、pending 清零或 LSP 成功都不等于业务分析完整。

## 先确认工作对象

- 定位平台仓库，读取 `callgraph.projects.json`，确认源码项目、任务场景和入口。不要把平台仓库误当作待分析项目。
- 服务地址优先取当前页面或用户指定值，通过 `/api/health`、`/api/graphs` 核实。端口不是固定的；V2 页面为 `/v2/?graph=<真实 slug>`。
- 复用已有服务，不为读图或写文档重启服务。不要在验收中修改用户的真实图。
- 用户仅要求评估/预览时停在草稿；要求生成并交付结果时，在既有授权范围内核验后保存，无需重复确认。未授权的回收站永久删除不属于整理图的隐含范围。

## 执行原则

1. 区分展示深度和采集深度。展开已有数据不调用 LSP；收起后看似叶子的节点不一定有续采资格。
2. 优先 CLI/API 完成数据操作，浏览器验证可读性和实际交互。API 必须使用服务返回的 slug、fileId、candidateId 和源符号 ID。
3. 新增、减枝和续采默认进入同一内存草稿。预览不保存；采纳/保存提交整份草稿，包括此前未保存修改。
4. 真实证据优先：源码行号是位置，不是运行时顺序；人工虚线和多态虚线需要结合边数据区分。
5. 不以视觉简洁为由删除真实必要分支。收起与隐藏解决阅读负担；减枝用于明确排除的业务范围。
6. 遇预算耗尽、无进展或解析失败，保留已获证据并报告边界，不无限续采或擅自扩大范围。

## 交付

提供可打开的图链接、入口与源码版本（能取得时）、已保存或仅草稿状态、校验结果和剩余不确定边界。围绕目标流程说明完成了什么，而非只报节点数量。

## 随项目维护

本目录是操作手册的版本化源。界面动作改变时更新 `references/workbench.md`；数据操作和持久化语义改变时更新 `references/analysis.md` 及 `docs/ai-operations.md`。不要把经典工作台能力直接当成 V2 能力。验证请求格式与当前实现一致；示例预算只是示例，不是全局完整度上限。
