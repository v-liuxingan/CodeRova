# 主干与支线叙事布局

## 问题

现有调用图使用广度优先层级布局。它能稳定表达调用方向，但第一次访问决定深度、同层按名称
排序，真实的分叉、汇合和跨阶段关系容易被压成一条纵向长链。源码步进器又默认选择一条
下游路径，进一步强化了“只有一条线”的感受。

本轮不追求展示完整静态调用图，而是让人工整理的场景调用图同时表达：

1. 这条场景的主要叙事路径。
2. 从主路径分出的备选、并行或辅助路径。
3. 多条路径重新汇合的位置。
4. 不等同于控制调用的跨阶段数据关系。

## 布局策略

新增 `NarrativeLayout`，通过现有布局抽象接入，保留 `LayeredLayout` 作为兼容实现。

### 主叙事脊柱

- 从 `graph.root` 开始计算稳定的主要路径。
- `direct`、`callback`、`trait-dispatch`、`spawn`、`remote` 和
  `async-boundary` 参与控制叙事。
- `data-flow` 默认不与控制调用争夺主路径；只有没有控制调用可以继续时才作为退化连接。
- 优先选择能够继续到达更多控制节点的路径；分数相同时按边 ID 稳定排序。
- 算法必须记录已访问节点，面对循环时安全终止。
- 多终点时允许选择一个主终点，其余终点作为支线保留，不能隐藏。

### 支线与汇合

- 主路径节点沿布局主轴保持同一条视觉脊柱。
- 主路径以外的节点根据其最近主路径祖先归入支线，左右交替并保持稳定顺序。
- 节点层级仍由有向关系决定，但同层顺序优先保持父子连续性，并使用重心排序减少交叉。
- 同一父节点、同一层级且显式带 `order` 的调用组成连续顺序带：纵向布局从左到右、
  横向布局从上到下递增，并围绕调用者居中。顺序带可以让其中的主路径节点暂时偏离视觉
  脊柱，避免序号与空间方向冲突。
- 已有手工位置覆盖继续拥有最高优先级；拖动顺序带中的单个节点只让该节点脱离自动位置，
  其余同级节点继续停留在顺序带坐标，不能整组退回旧的左右交替布局。
- `outDegree > 1` 的控制节点标记为分叉点，显示下游路径数量。
- `inDegree > 1` 的控制节点标记为汇合点，显示上游来源数量。
- 折叠、隐藏、边类型筛选后，根据当前可见图重新计算标记，不能显示过期数量。

### 关系分层

- `data-flow` 边先绘制到独立的背景关系层，使用弱化但可辨认的视觉样式。
- 控制调用边绘制在其上，主脊柱关系具有更高视觉权重。
- 选中或聚焦 `data-flow` 时恢复清晰度，仍可查看语义摘要和证据。
- 关系分层只改变表达，不改变筛选、选择、源码打开或步进语义。

## 视觉方向

延续当前工业化源码图谱语言，不增加通用卡片和装饰性动画：

- 主脊柱使用现有强调色形成连续但克制的方向感。
- 支线节点保留原节点样式，通过位置和细微层级差区分，不降低文字可读性。
- 分叉/汇合提示使用紧凑的 SVG 标记，例如 `3 PATHS`、`MERGE 2`。
- 数据流继续使用现有关系颜色和虚线语义，但降低默认不透明度。
- 横向和纵向布局都必须表达相同的主干/支线关系。

## 验收标准

1. `LayeredLayout` 保留，默认布局切换为独立的 `NarrativeLayout`。
2. 当前全部图在纵向、横向模式下都返回有限坐标且无异常。
3. 主路径节点沿主轴对齐，分支节点位于脊柱两侧，不依赖手工拖动。
4. 配置加载的四路分叉、shell orchestrator 的四路分叉可以在截图中直接辨认。
5. 分叉和汇合标记来自当前可见控制关系，折叠与筛选后会更新。
6. `data-flow` 默认处于背景层；选中后仍达到普通选中关系的可见度。
7. 节点拖动、布局持久化、折叠、隐藏、上下游聚焦、搜索和源码步进保持可用。
8. 布局结果具有确定性，同一输入连续计算得到相同位置。
9. JavaScript 语法检查、布局断言、Playwright E2E、Rust 回归和全部图源码校验通过。
