# 主干与支线叙事布局

## 问题

现有调用图使用广度优先层级布局。它能稳定表达调用方向，但第一次访问决定深度、同层按名称
排序，真实的分叉、汇合和跨阶段关系容易被压成一条纵向长链。源码步进器又默认选择一条
下游路径，进一步强化了“只有一条线”的感受。

本轮不追求展示完整静态调用图，而是让人工整理的场景调用图同时表达：

1. 这条场景的主要叙事路径。
2. 从主路径分出的备选、并行或辅助路径。
3. 多条路径重新汇合的位置。
4. 不等同于控制调用的跨阶段数据关系。

## 布局策略

新增 `NarrativeLayout`，通过现有布局抽象接入，保留 `LayeredLayout` 作为兼容实现。

### 主叙事脊柱

- 从 `graph.root` 开始计算稳定的主要路径。
- `direct`、`callback`、`trait-dispatch`、`spawn`、`remote` 和
  `async-boundary` 参与控制叙事。
- `data-flow` 默认不与控制调用争夺主路径；只有没有控制调用可以继续时才作为退化连接。
- 优先选择能够继续到达更多控制节点的路径；分数相同时按边 ID 稳定排序。
- 算法必须记录已访问节点，面对循环时安全终止。
- 多终点时允许选择一个主终点，其余终点作为支线保留，不能隐藏。

### 支线与汇合

- 主路径节点沿布局主轴保持同一条视觉脊柱。
- 主路径以外的节点根据其最近主路径祖先归入支线，左右交替并保持稳定顺序。
- 节点层级仍由有向关系决定，但同层顺序优先保持父子连续性，并使用重心排序减少交叉。
- 同一父节点、同一层级且显式带 `order` 的调用组成连续顺序带：纵向布局从左到右、
  横向布局从上到下递增，并围绕调用者居中。顺序带可以让其中的主路径节点暂时偏离视觉
  脊柱，避免序号与空间方向冲突。
- 已有手工位置覆盖继续拥有最高优先级；拖动顺序带中的单个节点只让该节点脱离自动位置，
  其余同级节点继续停留在顺序带坐标，不能整组退回旧的左右交替布局。
- `outDegree > 1` 的控制节点标记为分叉点，显示下游路径数量。
- `inDegree > 1` 的控制节点标记为汇合点，显示上游来源数量。
- 折叠、隐藏、边类型筛选后，根据当前可见图重新计算标记，不能显示过期数量。

### 关系分层

- `data-flow` 边先绘制到独立的背景关系层，使用弱化但可辨认的视觉样式。
- 控制调用边绘制在其上，主脊柱关系具有更高视觉权重。
- 选中或聚焦 `data-flow` 时恢复清晰度，仍可查看语义摘要和证据。
- 关系分层只改变表达，不改变筛选、选择、源码打开或步进语义。

## 视觉方向

延续当前工业化源码图谱语言，不增加通用卡片和装饰性动画：

- 主脊柱使用现有强调色形成连续但克制的方向感。
- 支线节点保留原节点样式，通过位置和细微层级差区分，不降低文字可读性。
- 分叉/汇合提示使用紧凑的 SVG 标记，例如 `3 PATHS`、`MERGE 2`。
- 数据流继续使用现有关系颜色和虚线语义，但降低默认不透明度。
- 横向和纵向布局都必须表达相同的主干/支线关系。

## 语义缩放与场景阶段

几何缩放同时控制信息密度，不把整张源码卡片等比例缩成不可读噪声：

- **场景概览层**：节点只保留用户职责；普通调用标签和源码位置隐藏，分支、回环和阶段仍可识别。
- **关系阅读层**：补充节点职责摘要和控制流说明，代码符号继续退居次要位置。
- **源码证据层**：显示函数名、crate、文件、行号和精确调用位置。

0.4 图可提供带布局顺序的 `phases`，节点通过 `phaseId` 归属阶段。独立的全画布场景地图
按 `phaseId` 聚合真实跨阶段边：相邻阶段形成阅读主干，具有明确控制语义的跨阶段关系形成
支线或回环；`branch / fallback / merge / loop-back / loop-exit` 使用对应的控制流
样式。普通非相邻捷径继续留在完整调用图中，不挤入概览。入口、判断、分支、回环和结果
直接写在节点中，避免再用一套需要猜测的抽象图标重复编码。

阶段拓扑与主调用图使用同一套 SVG 节点—边视觉语法：节点边框、左侧强调线、连接端口、
箭头以及分支和回环线型保持一致；区别只在信息层级——阶段节点使用用户场景语言，主图
保留可核验的代码事实。阶段节点同时显示用户职责摘要；阶段超过四个时使用两行主干，
跨行转折保持箭头方向，回环返回前序阶段。该布局优先保证阶段标题、职责、主干方向和
回环可读，不把阶段压缩成工具栏卡片。

拓扑根据真实阶段关系标记入口、判断、分支、回环和结果。具有多个明确控制流目标的阶段
显示为判断点；进入可选工具路径的阶段显示为分支；发出 `loop-back` 的阶段显示为回环；
没有后续关键关系的阶段显示为结果。角色文字必须可见，不能要求用户只凭抽象图标猜测。

场景地图不是第二份图数据，不维护人工阶段连线，也不改变原图执行语义。`phase.order`
只决定稳定排布，不宣称场景线性执行。具有阶段数据的图先进入场景地图；点击阶段后进入
调用细节层，弱化其他阶段并把所属真实节点居中。面包屑返回场景地图，两个阅读层分别
保存 viewport，切换时不重置缩放或节点布局。场景层暂时隐藏源码工作台和源码步进，进入
调用细节后恢复。阅读层级栏只显示场景标题层级，职责摘要由调用画布左上角固定的当前
阶段卡片承载。点击空白或按 Esc 可以取消临时高亮，但不会丢失下钻场景；点击固定阶段卡片
即可恢复该阶段高亮。进入或切换阶段时，源码步进器、节点详情和代码预览同步定位到该阶段
入口，避免视觉场景已经改变而 SOURCE WALK 仍停在旧分支。点击其他阶段的真实节点会直接
切换固定阶段卡片和高亮上下文，并给出场景切换反馈。用户通过“退出阶段聚焦”明确离开当前
下钻场景并返回完整调用图。
无阶段数据的旧图直接进入调用图。

图谱概览区把业务叙事和图结构分开：存在阶段时，`业务终点` 使用最后一个阶段表达用户
最终得到的结果，原始出度为零的节点另列为 `结构出口`；没有阶段数据时仍使用
`结构终点`。SOURCE WALK 的多下游菜单也不统一称为“分支”，而是根据真实边语义显示
`调用顺序`、`条件路径`、`异步路径` 或 `下游路径`，每个选项再标出直接调用、降级、
循环回边等具体关系。

## 验收标准

1. `LayeredLayout` 保留，默认布局切换为独立的 `NarrativeLayout`。
2. 当前全部图在纵向、横向模式下都返回有限坐标且无异常。
3. 主路径节点沿主轴对齐，分支节点位于脊柱两侧，不依赖手工拖动。
4. 配置加载的四路分叉、shell orchestrator 的四路分叉可以在截图中直接辨认。
5. 分叉和汇合标记来自当前可见控制关系，折叠与筛选后会更新。
6. `data-flow` 默认处于背景层；选中后仍达到普通选中关系的可见度。
7. 节点拖动、布局持久化、折叠、隐藏、上下游聚焦、搜索和源码步进保持可用。
8. 布局结果具有确定性，同一输入连续计算得到相同位置。
9. JavaScript 语法检查、布局断言、Playwright E2E、Rust 回归和全部图源码校验通过。
10. 适配全图时优先看到节点职责和关键控制语义，代码符号与调用位置仅在证据层出现。
11. 有阶段数据时先用全画布场景地图看到阶段主干、职责、跨阶段支线和回环；无阶段旧图
    直接进入调用图并保持原拖拽行为。
12. 场景地图关系完全从真实边聚合；阶段下钻和面包屑返回不改变原图节点、连线和布局，
    场景地图与调用图分别保持自己的 viewport。
